# 图片到食物的基础匹配逻辑

## 图片理解输出

图片理解层向匹配器提供标准化结果：

```json
{
  "ingredients": [
    { "name": "苹果", "confidence": 0.92 },
    { "name": "蜂蜜", "confidence": 0.61 }
  ],
  "color_groups": ["红", "黄"],
  "scene_affinity": ["秋日", "户外"],
  "intensity": "平衡",
  "season": "autumn",
  "scene_type": "relaxed"
}
```

`ingredients` 只放画面中能够直接看到、且置信度不低于 0.55 的水果或材料。不要根据场景猜测未出现的食材。

## 排序权重

| 信号 | 分值 | 说明 |
|---|---:|---|
| 第一项可见食材命中 | 最高 8 | 例如画面有苹果，优先含苹果的食物 |
| 后续食材命中 | 每项最高 4 | 两种材料同时出现时提高组合匹配 |
| 主色组命中 | 2.5 | 主体配色接近 |
| 辅色组命中 | 1.25 | 辅助配色接近 |
| 场景标签命中 | 每项 2.5，最高 5 | 例如秋日、海边、下午茶 |
| 氛围类型命中 | 2 | fresh、comfort 等 |
| 强度命中 | 1.5 | 轻盈、平衡、浓郁 |
| 季节命中 | 1 | `all` 也视为可匹配 |
| 惊喜扰动 | 0–0.9 | 只在近似候选间提供变化 |

可见食材是强信号，但不是硬过滤。排序后从前五名按分数加权抽取，避免同一张照片永远得到唯一答案。

低于 0.55 的食材识别不参与评分。没有识别出食材时，匹配器自然退回颜色、场景、氛围、强度和季节。

实现位于 `lib/matcher.mjs`，受控食材词与别名位于 `data/taxonomy.json`。

## 食材数据边界与调用

食物库的 `ingredient_tags` 是名称关联索引，不是图片可见性标注或完整配料表。名称不足以确认食材时允许为空，待核查条目保存在 `asset-audit/ingredient-review.json`。例如天妇罗不自动关联虾；燕麦奶、蟹柳、海底椰分别独立处理。名称提示词与物体识别别名分别保存，菜名不能作为识别别名。

调用时传入受控别名表：

```js
rankFoods(foods, profile, { ingredientAliases: taxonomy.ingredient_aliases });
```

凤梨与菠萝等别名归一后只计分一次，重复检测取最高置信度。对象形式必须提供 0–1 的有限数值置信度；低于 0.55、缺失或非法置信度均忽略。字符串形式表示调用方已经确认的食材，按 1 计分。

现有权重提供食材偏好，不保证每次都输出包含该食材的结果；多项场景信号和随机抽取仍会影响结果。当前仅完成数据索引与排序接口，网页尚未接入图像食材识别服务。

回归检查：`node scripts/check_ingredients.mjs`。
